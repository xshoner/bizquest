## 원인과 수정

1. **투자 금액 초기화**: 학생 컬렉션 실시간 수신마다 모든 투자 맵이 새 객체가 되었다. InvestmentStage의 useEffect가 객체 참조를 의존하여 다른 학생의 저장에도 편집 중 금액을 서버의 이전 값(대개 0)으로 덮어썼다. 이제 내용이 실제 바뀐 경우만 동기화하고 편집 중 값을 보호한다. 금액은 즉시 기기에 보관하고 400ms 후 서버에 초안으로 저장하며 저장 요청 순서와 최종 확정 우선순위를 보장한다. 예산·자기 팀 제외 제한을 유지한다.
2. **투자 화면**: 비교/빠른 투자 탭을 없애고 팀명·아이템명 카드 하나의 목록으로 통합했다. 카드에서 금액을 바로 조절하며 제목을 누르면 사업계획 팝업이 열린다. 평가는 양호/보통/취약 개수로 요약하고 ‘AI 평가 의견 보기’를 펼쳐야 총평과 항목별 근거를 보여준다. 팝업 영역/배경 클릭, 닫기, Escape로 닫힌다. 의견 펼침 조작은 닫기와 충돌하지 않는다.
3. **비정상 수익률**: 수업 설정 F16이 양호 5배/보통 2.5배/취약 0.75배, F17이 양호 3.5배/보통 1.07배/취약 0.78배였다. 예를 들어 +32% 이벤트가 F16 양호 5배로 +160%가 되어 복리로 누적됐다. 수익률의 ×100 중복 오류는 아니었다. F17도 양호의 손실 방어가 손실 증폭으로 바뀌어 있었다. 전역 효과 입력을 %로 분리하고 5 입력=5% 효과로 변환한다. 가산·방어 방향과 0~50% 범위를 검증하고 잘못 저장된 전역 값은 기존 코드 기본값으로 복구한다. 임의로 최종 수익률만 잘라내지는 않는다.
4. **재입장/중복 참여**: Firebase 초기 인증 복원이 끝나기 전에 currentUser만 검사해 signInAnonymously를 호출하던 경합을 제거했다. 방 코드 조회와 방 구독이 인증 복원 완료 및 하나의 공유 인증 요청을 기다린다. 같은 브라우저에서 QR 재접속 시 기존 UID의 팀·자가진단·투자·현재 단계로 복귀한다. 빈 캐시 학생 목록만으로 새 입장을 표시하지 않는다. 학생 생성은 트랜잭션에서 기존 문서가 없을 때만 수행하며 기존 상태를 초기화하지 않는다. 다른 UID가 기존 닉네임을 다시 등록하려 하면 안내한다. 같은 이름의 기록이 실제로 3개인 그룹과 2개인 그룹을 확인했지만 이름만으로 신원을 확정해 기존 참여자를 삭제하거나 합치지는 않았다.
5. **교사 강제 마감**: 사업계획은 현재 서버 초안(빈 팀은 빈 계획)을 잠그고 AI 평가로 진행한다. 투자는 유효한 미확정 서버 초안을 포함해 확정하며 실제 학생 기록을 다시 읽어 기업 출발 자산을 트랜잭션에서 고정한다. 오프라인 기기에만 남아 서버에 도착하지 않은 내용은 마감에 포함할 수 없다는 점을 화면에 안내한다.
6. **타이머**: 학생 화면 중앙에 반투명 빨간 1분/20초/5·4·3·2·1 알림을 표시한다. 포인터 이벤트를 가로채지 않으며 0초에 입력 잠금이나 단계 이동을 수행하지 않는다.
7. **관리자 색상**: 단순 문자 코드 기반의 탁한 색상 생성 대신 8개의 조화로운 색상쌍을 적용했다. 화면 진입 시 시작 색상을 무작위로 정하고 같은 화면에서는 갱신·필터링에도 각 팀 색상을 유지한다.

추가로 이벤트 예고와 적용을 트랜잭션으로 보호하고 이전 이벤트가 미적용 상태면 다음 월로 넘어가지 않게 했다. 새 시뮬레이션에서 이전 피벗·희석 플래그를 초기화한다. 비용·손실로 음수 자산이 발생해 이후 부호가 뒤집히는 계산을 차단한다. 최초 자본 필드가 있으면 해당 값을 수익률 기준으로 사용한다. 결과의 1위 유지 기간 집계도 12개월에서 24개월로 수정했다.
